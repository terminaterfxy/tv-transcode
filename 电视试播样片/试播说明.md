# 电视试播样片

> 样片文件不随工程保存，需要时运行 `zsh 生成样片.sh` 重新生成（约 1 分钟）。
> **2026-11-16 已在 LG G5 + Jellyfin 10.11.11 上测过一轮，结果和结论见文末。**

四段各 20 秒的合成样片：同一段 1080p 杜比视界 P8.1 彩条画面，音轨组合和容器不同。
用来确认一件事：**成品里多放一条原始无损音轨，会不会影响 LG G5 在 Jellyfin 里的直放。**

每条音轨里都有一句循环播放的中文语音，直接告诉你现在播的是哪一条，不用靠音调分辨：

| 音轨 | 你会听到 |
| --- | --- |
| EAC3 兼容轨（默认） | “现在播放的是 EAC3 兼容音轨” |
| TrueHD 原轨 | “现在播放的是 TrueHD 原始音轨” |
| DTS 原轨 | “现在播放的是 DTS 原始音轨” |

## 怎么测

1. 把四个视频文件复制到 NAS 的 `Movies`（测完删掉即可）。
2. 等 Jellyfin 扫描到，在电视上逐个播放。
3. 每个记三件事：
   - 有没有画面，电视有没有弹出杜比视界标志；
   - 默认有没有声音，语音说的是不是“EAC3 兼容音轨”；
   - Jellyfin 后台「活动」里这次播放是「直接播放」还是「转码」。
4. 试播 B、C、D 里再手动切到第二、三条音轨，看有没有声音、画面是否还正常。

## 每个样片回答什么问题

| 样片 | 回答的问题 |
| --- | --- |
| A 基准 | 现在的成品形态，应该正常。它不正常的话，其他几个的结果都不可信 |
| B MP4 + TrueHD | 杜比视界 MP4 里多一条 TrueHD，会不会破坏直放 |
| C MP4 + DTS | 杜比视界 MP4 里多一条 DTS，会不会破坏直放 |
| D MKV 全都有 | 新版 Jellyfin 声称 webOS 25 起杜比视界可以放在 MKV 里，G5 上是否属实 |

## 结果怎么用

- B、C 默认播放和 A 一样正常：把 `app.py` 里的 `KEEP_ORIGINAL_AUDIO_IN_MP4` 改成 `True`，
  以后杜比视界和原盘成品也保留原始音轨。
- D 有画面且点亮杜比视界：杜比视界成品可以考虑改回 MKV，原始音轨和原始图形字幕都能留下。
- 切到 TrueHD / DTS 轨没声音或触发转码：属于预期内，
  只要默认的 EAC3 轨正常就不影响日常观看。

## 2026-11-16 的测试结果

| 样片 | 默认播放 | 手动选其他音轨 |
| --- | --- | --- |
| A | 有画面，杜比视界亮，EAC3 | — |
| B | 与 A 相同 | 选 TrueHD 能出声，画面正常，起播卡顿 |
| C | 与 A 相同 | 选 DTS 能出声，画面正常 |
| D | 有画面，EAC3，**杜比视界不亮** | TrueHD、DTS 都能出声 |

结论：杜比视界成品继续用 MP4；MP4 里可以多带原始音轨（`KEEP_ORIGINAL_AUDIO_IN_MP4` 已开启）。
没记录的：每次播放是直接播放还是转码；选原轨后杜比视界是否还亮；电视端应用版本。
另：电视端不能在播放中切音轨，只能在播放前的详情页选。

换了电视、Jellyfin 大版本升级、或想验证新的成品形态时，重新生成样片再测一轮，并把结果追加在这里。
